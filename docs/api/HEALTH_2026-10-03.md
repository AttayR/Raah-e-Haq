## Production result

**0 of 19 checks passed.** Every request fails before HTTP:

```
* Connected to raahehaq.com (45.152.46.127) port 443
* error:1404B438:SSL routines:ST_CONNECT:tlsv1 alert internal error   (SSL alert 80)
```

Evidence that this is server-side, not the client network:

| Check | Result | Meaning |
|---|---|---|
| `https://www.google.com` from the same machine | 200 | The client network is fine |
| TCP to 45.152.46.127:443 | connects | The server is up |
| TLS with SNI `raahehaq.com` / `www.raahehaq.com` (TLS 1.2 and 1.3) | alert 80 internal_error | The server has **no SSL certificate configured for raahehaq.com** |
| TLS without SNI | presents `CN=*.hstgr.io` (Hostinger default) | Only the hosting provider's default cert exists |
| `http://raahehaq.com/` | `403 Forbidden` (LiteSpeed, `platform: hostinger`) | A Hostinger default page, not the app |
| `http://raahehaq.com/api/user` | `404`, HTML page | **The Laravel API is not answering at all**, even over plain HTTP |

## Conclusion

The production backend is **not reachable by the app**:
1. **SSL is missing.** The SSL certificate for `raahehaq.com` is not installed (or has expired or been removed) on the Hostinger server, so every HTTPS call fails. iOS ATS also blocks plain HTTP.
2. **The API isn't served.** Even over HTTP, `/api/*` returns a Hostinger 404 HTML page, not Laravel JSON. Either the Laravel app isn't deployed or linked to the domain anymore, or the domain's document root doesn't point at Laravel's `public/` folder.

**Impact:** login, OTP, registration and rides all fail in the app today, whatever the client code does. Client-side QA against production is blocked until this is fixed.
